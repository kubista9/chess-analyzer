## What was done

### Legacy cleanup (`scripts/clean-legacy-cache.mjs`, `npm run cleanup`, alias `npm run clean:legacy`)
- A dry run by default: each allow-listed item with its size, file count and a note, then the total and what is kept.
- `--yes` deletes; `--include-raw` adds `storage/cache/raw-games` (kept by default: the offline seed for `npm run sync -- --offline`). Unknown flags are refused.
- The allow-list:
  - `storage/tmp`;
  - `storage/cache/{scans, scans-v*, reviews, reviews-v*, snapshots}`;
  - `dist/storage`, `dist/server`, `dist/shared`, `dist/web`;
  - the root `.DS_Store`;
  - `public/`, only when it exists and is empty (critic).
- A protected list (`storage/chess.db*`, `storage/engines`, `storage/backfill.lock`, source dirs) makes the script throw rather than touch them.
- The output says `npm run build` is needed before `npm start` once `dist/` is gone (critic). With `--yes` it also removes an empty `dist/`.
- `--yes` was exercised only on a throwaway copy in the scratchpad, never on the repo. That run removed the allow-listed items and kept `chess.db`, `chess.db-wal`, `engines/` and `raw-games/`.
- `build:server` now clears `dist/server` and `dist/shared` before `tsc`, so deleted modules no longer linger in the build output (the stale `trainingPlan.js`, `batchAnalysis.js`, `chessCom.js` and others came from that).

### Resilience and accessibility
- `src/components/ErrorBoundary.tsx`: a class boundary with a fallback panel ("Something went wrong on this page", the error message, **Reload the page**) and `role="alert"`. It logs to the console. There is one around the whole app and one per route inside `AppShell`'s `<main>`. The route boundary is keyed by `location.pathname`, so navigating away clears the error.
- Mobile drawer (`AppShell.tsx`):
  - `isCompact` is initialised synchronously from `matchMedia("(max-width: 1180px)")`, so the first compact render already has the closed drawer `inert` and `aria-hidden`. Before, the first render assumed desktop, and the sidebar links were tabbable for one frame.
  - The closed drawer is `inert`, which replaces the per-link `tabIndex` juggling.
  - When open, the drawer is a labelled `role="dialog"` with `aria-modal`. The first nav link gets focus, Tab and Shift+Tab wrap inside the drawer, the top bar and `<main>` are `inert`, and Escape closes it.
  - On close (Escape, the close button, the backdrop, or a nav link), focus returns to the menu toggle.
  - The backdrop is a mouse target only (`aria-hidden`, `tabIndex -1`).
- P6 note (the sticky top bar covered the review's eval strip): `html { scroll-padding-top: var(--topbar-offset) }` with 80 px at ≤ 1180 px and 72 px at ≤ 520 px (bar height + 8). Every `scrollIntoView` (the review stage, the drill board) now lands below the bar. It replaces the Train stage's own `scroll-margin-top: 72px`.
- aria labels: a scan of every `<button>`, `<a>`, `<Link>`, `<select>` and `<input>` found no icon-only control without a label (the FilterBar checkbox is wrapped in its `<label>`). The drawer got its `aria-label`.

- The legacy route redirects (`/openings`, `/history`, `/dashboard`, `/review`) are gone; any unknown path already leads Home. `/training` → `/train` stays.

## Deviations

- **Script name**: the brief asked for `npm run cleanup` and P9.md for `npm run clean:legacy`, so both exist and point to the same script.
- **dist/**: the whole build output is listed (per P9.md), item by item. `dist/web` is fresh after every `npm run check`, but it is only build output. Instead of detecting stale files, `build:server` now wipes its own output first.
- **Env vars**: P9.md lists `ENGINE_NODES_*`, `OPENING_PLY_LIMIT`, `WINDOW_DAYS` and `CHESS_OWNER` as env vars. Only `CHESS_OWNER` exists (tests only). The others are code constants (the depth-based protocol replaced node budgets in P4a), and the README says so rather than documenting variables that do nothing.
- **"storage/user, archives, games-v*, positions"** from P9.md do not exist in this layout (everything is in `chess.db`). The protected list names what does exist.
- **"Add this position to drills" (optional)**: not done. It is more than a small change:
  - a manual flag in `content_json`;
  - `mergeCards` keeping manual cards;
  - `settleCheck` confirming a manual card whatever its loss;
  - the cap bypass;
  - a card at an EPD that regeneration later turns into a line card (the one-card-per-(colour, EPD) invariant that verify-cards checks);
  - a route, the review button and tests.
- **Smoke test without mutations**: the walkthrough did not press Sync, Start engine check, Seed from my games, Set as my move or Start session. Those write the owner's data or start long engine work. The drill board's scroll offset is covered by the same `scroll-padding-top` rule that was measured on the review.
